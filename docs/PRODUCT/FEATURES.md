# Product features

## Назначение

Карта функций `Still Thinking` по стадиям. Документ определяет scope, но не заменяет подробные задачи и acceptance criteria.

Основной пользовательский цикл:

`создать мысль → назначить возвращение → получить возвращение → переосмыслить → завершить или отложить снова`.

## Статусы стадий

- **Foundation** — техническая основа, необходимая MVP.
- **MVP** — минимальный законченный продуктовый цикл.
- **Beta** — качество и безопасность для ограниченного тестирования.
- **Post-MVP** — развитие после подтверждения основной ценности.
- **Experiment** — идеи без обязательства реализации.

# Stage 1 — Core MVP

## ONB-01. Первый запуск

Пользователь понимает:

- приложение не требует ежедневного ведения;
- мысль будет возвращена позже;
- данные хранятся локально;
- содержимое уведомлений скрыто по умолчанию.

## THO-01. Создание мысли

Пользователь может:

- ввести текст;
- сохранить мысль;
- увидеть validation для пустого ввода;
- отменить создание без сохранения.

## THO-02. Выбор срока возвращения

Варианты:

- завтра;
- через неделю;
- через месяц;
- конкретная дата и время;
- когда-нибудь без точной даты, если это включено в согласованный MVP.

Дата не может быть заведомо некорректной или находиться в прошлом.

## SCH-01. Return scheduling

- создаётся `ReturnSchedule`;
- база данных является источником истины;
- schedule можно перенести или отменить;
- просроченная запись определяется при запуске приложения;
- логика работает независимо от доставки уведомления.

## NOT-01. Локальное уведомление

- запрос permission в контексте понятной пользовательской пользы;
- нейтральный текст без мысли по умолчанию;
- отмена и перенос pending notification;
- отсутствие дубликатов;
- корректное поведение при denied permission.

## TOD-01. Экран Today

- показывает возвращённые мысли;
- не создаёт перегруженный inbox;
- корректно обрабатывает отсутствие возвращений;
- позволяет открыть следующий шаг reflection.

## REF-01. Переосмысление

Пользователь видит:

- исходную мысль;
- дату создания;
- контекстный вопрос;
- поле нового ответа.

## REF-02. Состояние мнения

Опциональная структурированная оценка:

- думаю так же;
- частично изменил мнение;
- больше так не думаю;
- пока не знаю.

## REF-03. Действия после reflection

- завершить;
- отложить повторно;
- отпустить;
- оставить открытой, если это соответствует модели состояния.

## TIM-01. Timeline мысли

- исходная запись;
- все reflections;
- даты возвращений;
- изменения статуса;
- итоговое состояние.

## ARC-01. Архив

Разделы:

- ожидают;
- вернулись;
- продолжаются;
- завершены;
- отпущены.

## ARC-02. Поиск

- локальный поиск по тексту;
- корректное empty state;
- поисковый запрос не логируется.

## SET-01. Базовые настройки

- настройка показа содержимого уведомлений;
- разрешённое время уведомлений;
- пауза возвращений;
- переход к privacy-настройкам.

## SEC-01. Локальная блокировка

- Face ID/Touch ID или код устройства через LocalAuthentication;
- корректный fallback;
- скрытие чувствительного интерфейса при уходе в background, если реализовано на этом этапе.

## DAT-01. Удаление данных

- удаление одной мысли и связанных сущностей;
- полное удаление локальных данных;
- явное подтверждение необратимого действия.

# Stage 2 — Beta readiness

## EXP-01. Экспорт

- экспорт данных в документированном локальном формате;
- отсутствие скрытой отправки на сервер;
- безопасная обработка share sheet.

## UX-01. Accessibility

- Dynamic Type;
- VoiceOver labels;
- достаточные tap targets;
- статус не передаётся только цветом.

## LOC-01. Локализация

- RU и EN;
- длинные строки проверены в Preview/Simulator;
- даты и plural forms локализованы.

## REL-01. Надёжность расписания

- восстановление pending notifications;
- смена часового пояса;
- изменение системного времени;
- удалённые/завершённые мысли не возвращаются повторно.

## MIG-01. Migration baseline

- первая versioned schema;
- проверка открытия существующего store;
- документированный порядок следующих migrations.

## QA-01. Beta diagnostics

- безопасные технические логи;
- отсутствие приватного текста;
- понятный экспорт диагностической информации без пользовательского содержимого;
- проверенная Release logging policy.

# Stage 3 — Post-MVP

Функции рассматриваются только после проверки основной механики:

## STH-01. Sealed thought

Мысль нельзя открыть до выбранной даты.

## PRM-01. Расширенная библиотека вопросов

- категории мыслей;
- разнообразие prompts;
- защита от повторения одного вопроса.

## WDG-01. Виджет быстрого ввода

Быстрое создание записи без открытия полного приложения.

## INT-01. App Intents / Siri

Создание мысли системной командой без передачи данных стороннему backend.

## SYN-01. CloudKit sync

Требует отдельного решения по конфликтам, privacy, tombstones и migrations.

## MED-01. Голос и изображения

Attachments не входят в MVP и требуют отдельной модели хранения и экспорта.

## INS-01. Личная статистика

Только описательная статистика без психологических диагнозов, scoring и давления.

# Stage 4 — Experiments

- умный выбор срока возвращения;
- контекстные возвращения;
- годовые капсулы;
- возврат мысли без показа даты/контекста до ответа;
- локальная классификация типа мысли;
- Apple Watch companion.

Эксперимент не добавляется в production roadmap без отдельной проверки ценности и privacy review.

## Явно вне scope текущего MVP

- backend;
- аккаунты;
- social/public feed;
- AI-психолог и диагнозы;
- сторонняя аналитика содержания;
- подписка и paywall;
- Android/web;
- CloudKit;
- голосовые записи и изображения;
- геолокация;
- XCUITest target.

## Правила изменения карты

При добавлении или удалении feature:

1. Указать stage и feature ID.
2. Описать пользовательскую ценность.
3. Указать зависимости.
4. Обновить `IMPLEMENTATION_PLAN.md`.
5. При изменении архитектуры обновить технические документы.
