# Tooling

## Цель

Закрепить порядок использования CodeGraph, Xcode MCP и CLI-инструментов.

## CodeGraph — основной инструмент навигации

CodeGraph MCP используется первым для:

- поиска файлов и символов;
- перехода к определению и использованиям;
- поиска callers/callees;
- анализа зависимостей между feature и слоями;
- оценки области влияния изменения;
- поиска существующей реализации похожего поведения;
- понимания структуры незнакомой части проекта.

### Рекомендуемый порядок

1. Найти ключевой symbol или feature через CodeGraph.
2. Посмотреть определения, usages и зависимости.
3. Сформировать минимальный список файлов для чтения.
4. Прочитать только релевантные фрагменты.
5. После изменения повторно проверить affected usages.

### Когда допустим fallback

Используй `rg`, `find`, `git grep` или ручное чтение, если:

- CodeGraph MCP недоступен;
- индекс ещё не построен;
- новые файлы не попали в индекс;
- запрос требует поиска текста, который CodeGraph не находит;
- нужно проверить generated/configuration-файлы вне индексируемого кода.

При fallback не выполняй широкий поиск по всему репозиторию без необходимости. Сужай запрос по каталогу, расширению и точному термину.

## Xcode MCP — основной инструмент интерактивной проверки

Соответствующий Xcode MCP используется для:

- открытия проекта/workspace;
- чтения Xcode diagnostics;
- проверки SwiftUI `#Preview` в Canvas;
- переключения Preview configurations;
- запуска приложения в Simulator;
- интерактивной проверки UI и пользовательского сценария;
- получения скриншота/состояния, если MCP это поддерживает.

Xcode MCP не заменяет воспроизводимые CLI-проверки. Build и test должны иметь команду, которую можно повторить локально и в CI.

## CLI-инструменты

### Xcode project и scheme

Не угадывай имена:

```bash
find . -maxdepth 3 \( -name "*.xcworkspace" -o -name "*.xcodeproj" \)
xcodebuild -list -workspace <Workspace>.xcworkspace
# или
xcodebuild -list -project <Project>.xcodeproj
```

### Simulator

```bash
xcrun simctl list devices available
xcodebuild -showdestinations -project <Project>.xcodeproj -scheme <Scheme>
```

### Lint

```bash
swiftlint lint --strict
```

### Build и tests

Команды определены в:

- `docs/WORKFLOW/XCODE_VALIDATION.md`;
- `docs/WORKFLOW/TESTING.md`.

## Правила выбора инструмента

- CodeGraph отвечает на вопрос «где и с чем связан код».
- Xcode MCP отвечает на вопрос «как код выглядит и ведёт себя в Xcode/Simulator».
- `xcodebuild` отвечает на вопрос «воспроизводимо ли проект собирается и проходят ли тесты».
- SwiftLint отвечает на вопрос «соответствует ли код установленным правилам».
- Git diff отвечает на вопрос «что фактически изменилось».

Нельзя заменять один тип проверки другим.

## Отчёт об инструментах

В итоговом сообщении укажи:

- использовался ли CodeGraph;
- использовался ли Xcode MCP и что именно проверено;
- фактические CLI-команды;
- какие инструменты были недоступны;
- какой fallback применён.

Не утверждай, что Preview просмотрен, если был проверен только build. Не утверждай, что зависимости проанализированы через CodeGraph, если использовался только текстовый поиск.
