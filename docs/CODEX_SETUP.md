# Настройка Codex и ведение AGENTS.md

## Назначение

Документ описывает организацию инструкций Codex в репозитории `still-thinking`.

Официальная документация OpenAI:

- https://developers.openai.com/codex/guides/agents-md

## Как загружаются инструкции

Codex формирует цепочку instruction-файлов от корня Git-репозитория к текущей рабочей директории.

В каждом каталоге приоритет имеет:

1. `AGENTS.override.md`;
2. затем `AGENTS.md`;
3. затем настроенные fallback-имена.

Более близкая к рабочей директории инструкция имеет больший приоритет.

Глобальные личные инструкции могут находиться в `~/.codex/AGENTS.md`, но проектные правила должны храниться в репозитории.

## Структура документации

```text
AGENTS.md
.github/
└── pull_request_template.md

docs/
├── CODEX_SETUP.md
├── DEVELOPMENT_WORKFLOW.md
├── WORKFLOW/
│   ├── DEVELOPMENT_PROCESS.md
│   ├── GIT_FLOW.md
│   ├── REPOSITORY_RULES.md
│   ├── TESTING.md
│   ├── TOOLING.md
│   └── XCODE_VALIDATION.md
├── ARCHITECTURE/
│   └── PROJECT_STRUCTURE.md
├── TECHNICAL/
│   ├── LOGGING.md
│   └── TECHNICAL_RULES.md
└── PRODUCT/
    ├── FEATURES.md
    └── IMPLEMENTATION_PLAN.md
```

Codex автоматически читает instruction-файлы. Обычные Markdown-документы подключаются через явные ссылки и требования из корневого `AGENTS.md`.

`docs/DEVELOPMENT_WORKFLOW.md` служит коротким индексом и определяет документы, которые нужно прочитать для конкретного типа задачи.

## Язык проекта

Codex должен использовать русский язык для:

- документации;
- комментариев и документирующих комментариев в коде;
- описаний Pull Request и Issue;
- review-комментариев и ответов;
- итоговых отчётов;
- отображаемых названий тестов Swift Testing.

Идентификаторы Swift, названия типов и методов, имена файлов и каталогов, названия веток, API и команды остаются на английском языке.

## Почему корневой файл короткий

Суммарный объём project instructions ограничен настройкой `project_doc_max_bytes`; по умолчанию это 32 KiB.

В корневом `AGENTS.md` остаются только:

- обязательный стек;
- основные запреты;
- правила CodeGraph и Xcode MCP;
- архитектурные границы;
- Git Flow;
- правила языка;
- обязательные проверки;
- формат итогового отчёта.

Подробные команды, чек-листы, карта функций и план реализации находятся в тематических документах.

## CodeGraph и Xcode MCP

Проект использует:

- CodeGraph MCP для поиска файлов, символов, использований и зависимостей;
- Xcode MCP для Preview, Canvas, диагностик Xcode и интерактивной работы с Simulator;
- `xcodebuild`, `simctl`, SwiftLint и Git CLI для воспроизводимых проверок и резервного выполнения.

Конкретные имена функций MCP не фиксируются: агент использует функции, реально доступные в текущей конфигурации сервера.

## Вложенные AGENTS.md

Вложенная инструкция создаётся только при локальных отличиях, например:

```text
Services/Notifications/AGENTS.md
Features/Reflection/AGENTS.md
```

Она не должна дублировать корневой файл.

`AGENTS.override.md` используется только при намеренной замене правил в конкретном каталоге, а не как постоянный способ обходить общие требования.

## Проверка загрузки

Из корня репозитория попроси Codex перечислить активные инструкции и проверь корень рабочей области через:

```bash
codex status
```

После изменения `AGENTS.md` начни новую Codex-сессию и повторно проверь активные инструкции.

## Правила обновления

1. Добавлять в `AGENTS.md` только постоянно применимые правила.
2. Использовать конкретные и проверяемые требования.
3. Не дублировать тематические документы.
4. Не ссылаться на несуществующие пути.
5. Локальные правила хранить во вложенном `AGENTS.md`.
6. При изменении процесса обновлять индекс и соответствующий тематический документ.
7. После изменения проверять размер файла и новую Codex-сессию.
8. Новую документацию и описания GitHub-сущностей писать на русском языке.

## Проверка размера

```bash
wc -c AGENTS.md
find . \( -name 'AGENTS.md' -o -name 'AGENTS.override.md' \)
```

При приближении к лимиту сокращай дублирование и выноси подробности в `docs/`.
